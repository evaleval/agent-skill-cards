# Skill Card: azure-kubernetes microsoft/azure-skills at 9aa7f618

## 1. What it does

| Field | Value |
|---|---|
| **Name** | azure-kubernetes |
| **Description** | Instructions, reference files, templates and two bundled sub-skills for planning, creating and running Azure Kubernetes Service (AKS) clusters with the Azure MCP server, az and kubectl. The base skill produces a recommended AKS cluster configuration that separates Day-0 decisions such as networking and API server access from Day-1 features, and covers SKU choice, security, observability, upgrades, node pools, reliability and cost, with focused workflows for pod rightsizing, VPA, the cluster autoscaler and Spot node pools. The azure-kubernetes-app-deploy sub-skill containerizes an existing app, generates a Dockerfile and Kubernetes manifests, validates them against Deployment Safeguards DS001-DS013 and deploys to an existing cluster, and the azure-kubernetes-automatic-readiness sub-skill assesses clusters or manifests for AKS Automatic compatibility and offers fixes as diffs. Use it to create, provision, design, secure or optimize AKS. |
| **Tasks** | • plan a production AKS cluster with a Day-0 checklist<br>• choose between AKS Automatic and Standard<br>• design AKS networking, security, observability and upgrades<br>• rightsize pods and set up VPA, the cluster autoscaler and Spot node pools<br>• run one ranked AKS cost review<br>• containerize and deploy an app to an existing AKS cluster<br>• assess clusters or manifests for AKS Automatic readiness |
| **Outputs** | • a recommended AKS cluster configuration with decisions and rationale, Day-0 separated from Day-1 (recommendation), text with az aks commands, to the conversation<br>• one ranked AKS cost report with lever, evidence, estimated cost impact, risk, approval needed and confidence (recommendation), table, to the conversation<br>• rightsizing patches, VPA objects and autoscaler, Spot and NAP settings (recommendation), YAML patches and az commands, to the conversation, applied after user confirmation<br>• AKS clusters, node pools, add-ons and autoscaler profiles created or changed (action), az aks create, az aks update and az aks nodepool calls, to the user's Azure subscription<br>• a Dockerfile, a .dockerignore and Kubernetes manifests such as k8s/deployment.yaml and k8s/service.yaml (information), files, to the project folder, manifests under k8s/<br>• a container image built in ACR and the app applied to the cluster with a rollout check (action), az acr build and kubectl apply, to Azure Container Registry and the AKS cluster<br>• a GitHub Actions workflow that builds, pushes and deploys on push to main (information), YAML file from templates/github-actions/deploy.yml, to the project, path not stated<br>• an AKS Automatic readiness assessment with a status summary and one entry per issue (information), Markdown tables and per-issue blocks, to the conversation<br>• fixes for AKS Automatic compatibility (recommendation), YAML diffs, to the conversation, written to the manifest files after approval<br>• a deployment summary and an architecture diagram with a monthly cost estimate (information), terminal text and a mermaid diagram, to the terminal |
