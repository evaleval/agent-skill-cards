## 1. What it does

| Field | Value |
|---|---|
| **Name** | semgrep |
| **Description** | Instructions, a shell scan runner and a Python SARIF merger for running a Semgrep security scan over a codebase. The agent detects languages and frameworks, selects official and third-party rulesets, presents the scan plan for explicit approval, then runs scripts/run-scans.sh, which clones the third-party rule repositories and runs semgrep with --metrics=off in batches. Out come per-scan JSON and SARIF files, a scans.json record of what ran, failed or was skipped, one merged results.sarif and a report by severity and category. Use it to scan code for vulnerabilities, run a security audit with Semgrep or do first-pass static analysis. |
| **Tasks** | • detect languages, frameworks and Semgrep Pro availability<br>• select official and required third-party rulesets per language<br>• present the scan plan and wait for explicit approval<br>• run semgrep scans in parallel batches with metrics off<br>• filter to important-only security findings at medium-to-high confidence and impact<br>• merge all results into one deduplicated SARIF file<br>• report findings and every scan that failed, was skipped or covered nothing |
| **Outputs** | • the scan plan with target, engine, mode, detected languages and every ruleset (recommendation), a message to the user, to the conversation, approved or edited by the user at Step 3<br>• the approved plan and the record of what ran, failed, was skipped, partial, oversized or covered nothing (information), JSON files, to $OUTPUT_DIR/rulesets.json and $OUTPUT_DIR/scans.json<br>• raw per-scan results, unfiltered, and the important-only filtered copies (information), JSON and SARIF files named &lt;language>-&lt;ruleset> or all-&lt;ruleset>, plus *-important.json, to $OUTPUT_DIR/raw/<br>• merged and deduplicated findings (information), SARIF file, to $OUTPUT_DIR/results/results.sarif<br>• the scan report with files scanned, rulesets used, findings by severity and category, and scans that did not run (information), a message to the user, to the conversation |
| **Sample output** | `Total findings: 156` |
| **Inputs** | • the codebase to scan, an absolute directory path, required for every task, example `/static-analysis:semgrep-scan {"target": "/abs/path", "mode": "run-all"}`<br>• an output directory, a directory path in the user's prompt, optional for every task, example `./static_analysis_semgrep_1`<br>• the scan mode, a choice of run all or important only, required for every task, example `Run all (Recommended)`<br>• approval of the scan plan, an explicit reply from the user, required for every task before scanning, example `"yes", "proceed", "approved", "go ahead", "looks good", "run it"`<br>• the approved rulesets, a rulesets.json file with baseline, one key per language and third_party URLs, required for running scripts/run-scans.sh, example `--rulesets "$OUTPUT_DIR/rulesets.json"`<br>• scanner options for the Pro engine, parallel jobs and the file size limit, flagged arguments of run-scans.sh, optional for running scripts/run-scans.sh, example `` `--jobs N` sets how many semgrep processes run at once (default 4) `` |
