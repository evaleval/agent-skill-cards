## Filling guide, Version (Skill Card v1.3)

How each field of the sixth section is filled. The guide is for the pipeline and for anyone generating a card by hand or with a model. It is not part of the card. A row holds one value per source that speaks, the author's files, a registry, a check, the assembler's model or a reviewer, each with its marker, and values that disagree all stand. An empty value is always written as unknown, not examined, none or not declared, never left blank. When no check covered a field, the check value reads not examined. All three fields are computed by the assembler, with the author's version string quoted where there is one.

| Field | How to fill |
|---|---|
| version | Record the hash scheme and compute the hash with that scheme. `skill-tree-v1` hashes regular files with sha256 over sha256sum-style rows: the lowercase hexadecimal sha256 of the file's content, two spaces, and the path relative to the skill folder with forward slashes, each row ended by a line feed, rows sorted by path as bytes. `skill-tree-v2` keeps those rows and adds each symbolic link as a typed row containing the sha256 of the link target text; the target is not followed or copied. File modes are not part of either hash. Exclude only documented out-of-skill items, record each excluded path and reason, and retain a digest when the excluded item was read as a file. A license file is part of the skill and stays in. Compare hashes only when the scheme matches and the exclusion records are compatible. Record the author's own version string from the frontmatter or metadata and the commit at which the files were read, when they exist, as quoted values. When the frontmatter has no version string, record not declared, and when the source is not a repository, record none for the commit. |
| source | Record the location the files were taken from with enough detail to fetch the identical files later. This is a repository address with the commit at which the files were read and the path inside it, a registry name with its version string, or a local path. Add the date on which the files were retrieved. When a tool produced the files, for instance a compiler from a specification or a generator from a template, add one clause naming the tool with its version, the input it worked from and the date, as the files or their metadata state it. Nothing else about the tool is recorded here or in any other row. A local path counts as a source, so the field is never empty for a skill the pipeline has read. |
| file list | List every regular file and symbolic link with its path, byte size, sha256, object type, content kind, hash membership and executable mark. For a symbolic link, the byte size and sha256 describe the target text; never follow or copy its target. Mark a file left out of the tree hash with a reason. Add the kind of each regular file as script, document, data or binary. A file is a script when its content is a program, for example it parses as Python or shell or starts with a shebang line. It is a document when its content is prose or markup, even when it contains code examples. It is binary when its content does not decode as text, and data otherwise. A symbolic link's kind is data because its target is not read as a file. Add the count of files per kind, computed. Trace files or reports that a producing tool left next to the skill are counted and listed as left out, not described. |
