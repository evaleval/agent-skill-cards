## Filling guide, Who stands behind it

How each field of the fifth section is filled. The guide is for the pipeline and for anyone generating a card by hand or with a model. It is not part of the card. A row holds one value per source that speaks, the author's files, a registry, a check, the assembler's model or a reviewer, each with its marker, and values that disagree all stand. An empty value is always written as unknown, not examined, none or not declared, never left blank. When no check covered a field, the check value reads not examined. A statement by the publisher outside the skill folder, for instance in the readme of the repository the skill came from, or a license the hosting platform detects, is a registry value with a link.

| Field | How to fill |
|---|---|
| authorship | Record the author, the publisher or owner, the signer if the files are signed, and a contact, each as the files or the registry state them, from the frontmatter metadata, a copyright line in a license file, a readme, or the registry's owner or publisher entry, with file and line or a link. The organisation or account that owns the source location is recorded as the publisher the source shows, computed from the source. A contact is an address or a page the files or the registry name for questions or problems, and when the registry names only its own owner's address, record that address marked as the registry owner's. Authors of commits in the repository history are not authorship values. A tool that produced the files is not an author, it is recorded under source. For the signer, record who signed, with which scheme, which files the signature covers, who verified it and when. A signed commit or release of a repository that contains the skill attests the commit, not the skill files, and does not count. Record none for the signer when the folder and the registry were checked and no signature was found, and unknown when nobody looked. Record not declared for every part no place states. |
| license | Record the license as each place states it, the license field of the SKILL.md frontmatter quoted, the name or title a LICENSE file gives itself, or its first line when it gives none, with file and line, and the license the registry shows with a link, each as its own value. Licenses of third-party libraries that the files list are not the skill's license and are not recorded here, and the terms of a service the skill calls are recorded under cost. Record not declared for a place that states nothing. Do not map a statement to a standard identifier or judge what it permits. |
| maintenance status | Record the date of the last change to the skill's content, meaning the last change that altered the folder hash, as the source records it, with the commit or registry entry, and follow the folder across renames when tracing its history, because a repository's log stops at each move. Record the registry's own update date for the skill's entry when the registry keeps one, otherwise not declared. Record any deprecation notice the files or the registry carry with file, line or link, and not declared when none is stated. Record the release cadence as computed from the source, the number of content changes since the skill first appeared and whether releases or tags exist, and a version number of a manifest that covers several skills is not a release of this skill. Record unknown when the source keeps no history. |
