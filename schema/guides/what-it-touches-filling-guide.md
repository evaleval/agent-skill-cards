## Filling guide, What it touches

How each field of the third section is filled. The guide is for the pipeline and for anyone generating a card by hand or with a model. It is not part of the card. A row holds one value per source that speaks, the author's files, a registry, a check, the assembler's model or a reviewer, each with its marker, and values that disagree all stand. An empty value is always written as unknown, not examined, none or not declared, never left blank. When no check covered a field, the check value reads not examined. The Author value in this section holds what the files state or contain literally, a sentence in SKILL.md, a field in the frontmatter, or a host name, path, variable name, command or program that appears in a document or a script, quoted with file and line. Commands and file names in code examples count, because the skill instructs the agent to use them. Anything inferred from the files, for instance that a shell tool is needed because the agent is told to run a command, or that a script overwrites files because it opens them for writing without checking, is recorded as a separate value marked model-generated with the passage as evidence. Anything found by tracing or running code is a check value with a pointer into the check's report. A none value states what was scanned and carries the marker computed.

| Field | How to fill |
|---|---|
| side effects | Record whether the skill is read only or changes state, then one entry per kind of change, for instance creates files, overwrites files, changes a file in place, installs packages, sends a message, moves money or deploys a service, with what it affects, whether the files say a confirmation is asked first as yes, no or not declared, and whether the change is reversible as yes with the way to undo it, no, or not declared. A command in an example counts as a change the skill instructs. Take the Author entries from statements in the documents and from literal file, process and network operations in the scripts, with file and line. Confirmation and reversibility are Author values only when the files state them, an inference from the code is a model-generated or check value. Record not examined when no check covered the scripts. |
| network access | One entry per host or service the skill contacts when it is used or installed, with the host name or pattern and a link to the service, whether the connection is required, optional or conditional, whether the host is named in the files or formed at run time from variables, what the connection is for in plain words, for instance the weather service the answers come from, the data that goes to the host and the data that comes back, as the files state it, and the retention where the files say, otherwise not declared for the retention part. Content the skill sends to a second model or service is its own entry. A link in documentation or license text is not a connection. An install command is a conditional connection to a package index with the host not named. Add one summary line reading none, listed hosts or any. Take the Author entries from literal addresses and commands in the documents and scripts, with file and line. Record none when the files name no host, and not examined when no check covered the scripts. |
| tools and permissions | One entry per tool with its name, its kind as agent tool, shell command, program invoked, or external server, where in the skill it is used with file and line, the purpose the files state, and whether it is built into the runtime or comes from a third party as far as the files say, otherwise unknown. The allowed-tools field of the frontmatter and body statements about the tools, servers, protocol versions and permissions the runtime must offer are Author entries, quoted in full. The programs and commands the files tell the agent to run are Author entries. The agent tool needed to run them is a model-generated entry unless the allowed-tools field or a statement names it. An install command is recorded here as a shell command and under software dependencies as what it installs. Record none when the files name nothing, and not examined when no check covered the scripts. |
| machine access | One entry per path or naming pattern and operation, the operation as read, write or delete, where an in-place change is a write, the scope as workspace, skill folder, outside the workspace or system, and where the files state it with file and line. A relative path in a document is a workspace pattern, a path relative to the skill's own folder is in the skill folder, and a path the agent chooses at run time is recorded as such with scope unknown. For a script, record the kinds of path it reads and writes rather than every call. Then one entry per environment variable or configuration item other than a secret, with its name, whether the skill reads or sets it, and the reason the files give, or none given. Take the Author entries from literal paths and names in the documents and scripts. Record none when the files name nothing, and not examined when no check covered the scripts. |
