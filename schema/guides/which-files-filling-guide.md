## Filling guide, Which files exactly

How each field of the sixth section is filled. The guide is for the pipeline and for anyone generating a card by hand or with a model. It is not part of the card. A row holds one value per source that speaks, the author's files, a registry, a check, the assembler's model or a reviewer, each with its marker, and values that disagree all stand. An empty value is always written as unknown, not examined, none or not declared, never left blank. When no check covered a field, the check value reads not examined. All three fields are computed by the assembler, with the author's version string quoted where there is one.

| Field | How to fill |
|---|---|
| version | Compute the hash with sha256 over a list of the files, written in the format of the sha256sum utility, one line per file with the lowercase hexadecimal sha256 of the file's content, two spaces, and the path relative to the skill folder with forward slashes, each line ended by a line feed, lines sorted by path as bytes. File modes are not part of the hash. Leave out only documents about the skill that are stored next to it, for example a skill card, a benchmark report or the trace files of a producing tool, and list what was left out. A license file is part of the skill and stays in. Record the author's own version string from the frontmatter or metadata and the commit at which the files were read, when they exist, as quoted values. When the frontmatter has no version string, record not declared, and when the source is not a repository, record none for the commit. |
| source | Record the location the files were taken from with enough detail to fetch the identical files later. This is a repository address with the commit at which the files were read and the path inside it, a registry name with its version string, or a local path. Add the date on which the files were retrieved. When a tool produced the files, for instance a compiler from a specification or a generator from a template, add one clause naming the tool with its version, the input it worked from and the date, as the files or their metadata state it. Nothing else about the tool is recorded here or in any other row. A local path counts as a source, so the field is never empty for a skill the pipeline has read. |
| file list | List every file in the folder with its path, its size in bytes and the sha256 of its content. Mark the files that were left out of the folder hash, and mark files whose mode makes them executable. Add the kind of each file as script, document, data or binary. A file is a script when its content is a program, for example it parses as Python or shell or starts with a shebang line. It is a document when it is prose or markup, even when it contains code examples. It is binary when its content does not decode as text, and data otherwise. Add the count of files per kind, computed. Trace files or reports that a producing tool left next to the skill are counted and listed as left out, not described. |
