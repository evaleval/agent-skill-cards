## Filling guide, What it needs

How each field of the second section is filled. The guide is for the pipeline and for anyone generating a card by hand or with a model. It is not part of the card. A row holds one value per source that speaks, the author's files, a registry, a check, the assembler's model or a reviewer, each with its marker, and values that disagree all stand. An empty value is always written as unknown, not examined, none or not declared, never left blank. When no check covered a field, the check value reads not examined. The Author value holds what the files state, a requirement named in the frontmatter, a compatibility statement, an install instruction, an import or a command in a script. What an instruction to the agent merely implies, for example that the model must see images because the agent is told to analyse one, is not recorded in this section.

| Field | How to fill |
|---|---|
| compatibility | Record each model, capability and harness the files name as needed, from the frontmatter, the compatibility statement and the body, a capability being one of tool calling, vision, code execution, structured output or long context with the size named, with file and line, and quote the compatibility statement in full. Record not declared when the files name none. A check that ran the skill records the capabilities the run actually used as a separate value. Then add, computed by the assembler, one line per harness on the list, as fits, fits with a display cut naming the limit, does not fit with the rule broken, or not checked. A display cut is a limit that shortens what a reader or an agent sees, such as a listing or a summary, and a broken rule is a limit that refuses or truncates the skill itself. The rules checked today, verified on 12 October and tabled in the handoff of that date, are these. The Agent Skills specification requires name, at most 64 characters, lowercase letters, numbers and hyphens, matching the folder name, and description, at most 1,024 characters, allows compatibility up to 500 characters, and recommends a SKILL.md body under 500 lines and under 5,000 tokens, where tokens are estimated as bytes divided by four and the estimate is marked as such. Codex cuts a description at 1,024 characters, an injected SKILL.md at 8,000 bytes measured over the whole file as stored, the skills listing at 8,000 characters or 2 percent of the context window with a cap of 10,000 tokens, a name at 256 bytes and a path at 1,024 bytes. Claude Code treats every frontmatter field as optional, recommends description, cuts listing text at 1,536 characters and recommends a SKILL.md under 500 lines. ClawHub caps a bundle at 50 MB, stops analysing at 256 KB and shows a 300 character summary. Whether Codex and the specification count the frontmatter in their byte and line limits is to be verified and is noted in the open list. A program that is run as code and not loaded by a harness records runs as a program for this part. The list of harnesses grows as the volunteer task delivers them, and a harness not on the list reads not checked. |
| software dependencies | List each dependency with its name, its kind as package, runtime, binary or hardware, its version where stated, and where it comes from, as an install instruction or requirements file, an import or a program invoked in a bundled script, or an import or a command in a code example in the documents, with file and line. A dependency from a code example is marked as belonging to that example, because it is only needed when the agent follows it, and alternatives such as a second language route are marked as alternatives. A service the skill calls over the network is not a software dependency, it is recorded under network access. Transitive needs that the files do not state are not listed in the Author value, a check may add them as its own value. The Author value holds what the files state, a check that analysed the scripts holds what the code actually imports and calls. Record none when the scripts were analysed and need nothing, not declared when the files do not say, and not examined when no check covered the scripts. |
| credentials | One entry per kind of secret, one of API key, token, password, certificate or other, with what it is used for, where the skill gets it, for instance an environment variable name, a prompt to the user, or a value the agent supplies in a command, and where it goes, as stays on the machine passed to a program, or leaves the machine to a named host, or unknown. A placeholder secret in an example command counts as a secret the skill handles. Take the Author entries from statements in the documents and from literal variable names, prompts and command lines in the documents and scripts, with file and line. The value of a secret is never written anywhere on the card. Record none when the files were read and name no secret, and not examined when no check covered the scripts. |
| cost | Compute the context part from the size of the description, of SKILL.md and of each file the instructions tell the agent to read, in bytes and as a token estimate at four bytes per token marked as an estimate, and record separately what is loaded at discovery, at load and on demand. Record the tokens a run consumed only as an evaluation measured them, citing the run, otherwise not examined. Then record each external service the files say the skill uses that has a price, a quota or a rate limit, with what the files state about its terms, quoted with file and line, and record not declared when the files name such a service, for instance by demanding its API key, but say nothing about its terms, and none when the files name no such service. Record the number of calls one use makes where the files state it. Never compute or estimate a price, and running time is not part of this field. |
