## Filling guide, What it does

How each field of the first section is filled. The guide is for the pipeline and for anyone generating a card by hand or with a model. It is not part of the card. A row holds one value per source that speaks, the author's files, a registry, a check, the assembler's model or a reviewer, each with its marker, and values that disagree all stand. An empty value is always written as unknown, not examined, none or not declared, never left blank. When no check covered a field, the check value reads not examined. The summary and the task list in description are the only model-written text in this section, everything else is quoted, computed or read from a registry.

| Field | How to fill |
|---|---|
| name | Quote the name field from the SKILL.md frontmatter exactly as written, with its case and punctuation. If the frontmatter has no name field, record the folder name and mark the value as computed. Whether the name meets a harness's rules on length, characters or agreement with the folder name belongs under compatibility. |
| description | Write the summary first, marked model-generated, in two to four sentences that say what the skill does, on what material, what comes out and when the agent should use it, with every sentence taken from a passage in the files cited with file and line and nothing taken from knowledge outside the files. For a skill that acts rather than produces, the summary says what it does, for instance that it deploys the project and returns the address. Then list the tasks the skill covers as three to seven short phrases, each quoted from the files or built from a cited passage and marked accordingly, and include among them statements of where and for whom the skill works, such as a region, a language, a single installation or a posture like research only, when the files make them. Then quote the description field from the SKILL.md frontmatter in full and without edits, marked quoted, and record not declared when the frontmatter has none. If a registry carries its own description of this skill, record it as a further value marked registry, where a registry is a separate index with an entry for this skill and the description of a bundle that contains several skills does not count. Use-when sentences in the body are not quoted here or anywhere, the author's description is the trigger text. This is the only summary on the card, every other row quotes, computes or classifies. Whether the author's text fits the discovery limits of each harness belongs under compatibility. |
| outputs | List one entry per kind of result, for instance a filled PDF, page images, a JSON list of fields, a message to the user or a deployment, with its format and where it ends up, a path or naming pattern the files state, a path the agent chooses, a message to the user, or an action through a tool, citing one place in the files for each with file and line. File names in code examples and in workflow steps count as statements of what the skill produces, and intermediate files a workflow leaves on disk count as outputs. Say for each kind whether it is information the reader uses, a recommendation the reader is meant to act on, or an action the skill carries out, as the files state it, because a reader who delegates a decision needs to know whether the skill makes one. Add one sample of a result, quoted from an example in the files with file and line or taken from an evaluation run with its id, never written by the model, and record not declared when the files show none and not examined when no run took place. For a skill whose result is an action, the sample is the message or record the files show for a completed action. A check that ran the skill or analysed its scripts records what was actually produced as a separate value. Record not declared when the files do not say what the skill produces. |
| inputs | List one entry per kind of input, for instance a PDF file, an output directory, a JSON file of field values or a question in natural language, with its form and whether it is required or optional, taken from statements in the documents and from the argument definitions and usage lines of bundled scripts, with file and line. A positional script argument is required, a flagged one is optional unless the script says otherwise. File names in code examples are not inputs, the kind of file they stand for is. The user's request is an input only when the files say what it must contain. Add one example value per input as the files give it, for instance a sample command line, a sample request or a sample file name, with file and line, and record not declared when the files give none. Record what the skill does when an input is missing or ambiguous, as the files state it, for instance that it asks the user for a location, and not declared when they do not. A check that analysed the scripts records the parameters they actually read as a separate value. Record not declared when the files do not say, and not examined when no check covered the scripts. |
| exclusions | An exclusion names a use the skill is not meant for, a task, a domain, a situation or a setting, stated anywhere in the skill's files with phrases such as not for, do not use for, not intended for, not suitable for, not outside or only inside. A statement that the skill must not run in production or in a named setting is an exclusion. List one entry per exclusion with file and line. A prohibition on a technique inside a workflow, for instance never to use a certain character, is an instruction, a statement of what the skill cannot do is a limitation, and a term of the license is recorded under license, so none of them belong here. Record not declared when the files contain none. A reviewer may add an exclusion, marked review. Checks never write here, what a check found goes to risks or vulnerabilities. |
| adoption | Record downloads, installs, stars, likes or any other count of use exactly as the registry shows it, with the date it was read and a link, one entry per registry, and a count for a period only when the registry itself shows one. Name the thing each count belongs to, and when the only counts available are those of a repository that contains the skill among other things, record them as the repository's. Never compute or estimate a number here. Record not declared for a registry that shows none, and none when the skill is in no registry. |
